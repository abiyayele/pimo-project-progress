Knowledge migration design

Current agreed operating model.

1 · Google Drive remains the team workspace

Staff continue adding and editing files in Google Drive. Pimo reads from a controlled NAS mirror rather than forcing a workflow change.

2 · NAS mirror is change-driven

A persistent Drive Changes API checkpoint identifies only new and modified files. The delta worker runs every 30 minutes and avoids repeatedly traversing the entire source tree.

3 · Classify before embedding

Useful business documents, including relevant XML and JSON from Immoware24 mappings/scrapes, are parsed and indexed; software binaries and low-value technical artifacts remain stored but are not embedded.

4 · Re-index only what changes

PostgreSQL tracks source identity and processing state. Changed documents invalidate downstream chunk/embedding state, obsolete vector references are cleaned safely, and the fresh document can return to retrieval.

Next delivery sequence

Resume point for the next implementation phase.

1 · Controlled indexing expansion

Expand chunking and embedding in bounded batches, monitor errors and storage growth, then move toward a production Qdrant collection.

2 · Retrieval quality & access control

Test representative business questions, improve ranking where needed, and enforce policy metadata before documents can be returned to users.

3 · Embedding worker resilience

Add recovery for abandoned EMBEDDING states and improve vector-update ordering so transient Qdrant failures cannot unnecessarily discard a previous good representation.

4 · Implement control plane

Create users, roles, permissions, object access, tasks, approvals, audit events and agent-run persistence before real agent actions are enabled.
