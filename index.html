Knowledge migration design

Current agreed operating model.

1 · Google Drive remains the team workspace

Staff continue adding and editing files in Google Drive. Pimo reads from a controlled NAS mirror rather than forcing a workflow change.

2 · NAS mirror is incremental

An hourly rclone copy pulls new and modified files into the NAS mirror. Copy semantics intentionally avoid automatically deleting NAS copies when a source item is removed.

3 · Classify before embedding

Useful business documents are parsed and indexed; software files, binaries, archives, media assets and low-value technical artifacts remain stored but are not embedded.

4 · Re-index only what changes

PostgreSQL will track file identity and indexing state so new or modified documents are processed incrementally instead of rebuilding the entire corpus.

Next delivery sequence

Resume point for the next implementation phase.

1 · Build document registry

Create PostgreSQL metadata/state tracking for file IDs, source paths, modification times, hashes, permissions, parsing and indexing status.

2 · Build ingestion pipeline

Parse approved document, email and spreadsheet formats while preserving source metadata and restricted-domain classification.

3 · Activate incremental RAG

Chunk content, generate embeddings, write vectors to Qdrant and validate retrieval quality against representative business questions.

4 · Implement control plane

Create users, roles, permissions, object access, tasks, approvals, audit events and agent-run persistence before real agent actions are enabled.
