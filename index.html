Knowledge migration design

Current agreed operating model.

1 · Google Drive remains the team workspace

Staff continue adding and editing files in Google Drive. Pimo reads from a controlled NAS mirror rather than forcing a workflow change.

2 · NAS mirror is change-driven

A persistent Drive Changes API checkpoint identifies only new and modified files. The delta worker runs every 30 minutes and avoids repeatedly traversing the entire 482k-file source tree.

3 · Classify before embedding

Useful business documents, including relevant XML and JSON from Immoware24 mappings/scrapes, are parsed and indexed; software binaries and low-value technical artifacts remain stored but are not embedded.

4 · Re-index only what changes

PostgreSQL tracks source path, source identity, modification metadata and indexing state so changed documents return to DISCOVERED while unchanged documents keep their processing state.

Next delivery sequence

Resume point for the next implementation phase.

1 · Build ingestion parsers

Parse approved document, email, spreadsheet and structured XML/JSON formats while preserving source metadata and restricted-domain classification.

2 · Normalize and chunk content

Create consistent processed-document output, extract metadata and prepare content for embedding without losing source traceability.

3 · Activate incremental RAG

Generate embeddings, write vectors to Qdrant and validate retrieval quality against representative business questions and access rules.

4 · Implement control plane

Create users, roles, permissions, object access, tasks, approvals, audit events and agent-run persistence before real agent actions are enabled.
